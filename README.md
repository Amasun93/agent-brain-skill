# Agent Brain Skill

> 让任何 Agent 装上就能"真正记住你"——跨 session、跨平台、可沉淀的轻量级长期记忆系统

---

## 一句话介绍

**agent-brain-skill** 是面向 AI Agent 的**记忆增强系统**。把"用户认知"沉淀到文件 + Git 仓库，会话开始时 Agent 自动加载关键信息，会话结束自动 commit 沉淀。**零依赖、跨平台、即装即用。**

---

## 它解决什么问题

Agent 在长期协作中普遍卡在三件事：

### 1. 跨 session 失忆
每次新开对话，Agent 从零开始——昨天的决策、上周踩过的坑、你的核心偏好，全要重新交代。

**本系统做法**：把"你是谁、你关心什么、你们之间经历过什么"沉淀到 Git 仓库的 `brain/` 目录。新会话开始时 Agent 自动 `git pull` 加载 `index.md` + 关键认知文件，会话结束自动 commit 写回。**下次再聊，不用再说一遍。**

### 2. 记忆没有分层
传统笔记把所有信息平等对待——一周前的闲聊和十次对话才提炼出的"你作息偏好的规律"被放在同一级，Agent 不知道哪些重要、哪些可以忽略。

**本系统做法**：**五层认知架构**（L1 状态 → L5 核心特质），不同层级有不同写入门槛和清理策略。深层认知（L4/L5）变更需用户确认，不会被 Agent 误改。

### 3. 没有沉淀钩子
"提醒 Agent 沉淀"靠用户自觉，Agent 自己不会主动总结；或者过度依赖 LLM 自动总结，token 消耗巨大。

**本系统做法**：**6 个生命周期钩子**（会话开始 / 新观察 / 矛盾检测 / 证据积累 / 会话结束 / 定期治理）在恰当的时机自动触发沉淀，**用户不催也能写**。整个系统用 Node.js 内置实现相似度合并和重复检测，不调用任何外部 API，不引入任何 npm 包。

### 4. 长会话信息丢失（v2.2 新增）
Context 压缩、长任务分多次执行时，Agent "忘了"自己早期的决策或用户偏好；新信号直接占 L3/L4 槽位，污染认知层。

**本系统做法**：**WAL 协议**（先写 `brain/SESSION-STATE.md` 再回复用户）+ **两阶段工作流**（新信号先入 `brain/pending/` 毛坯区，待证据积累后再 promote 到 cognition/）。两个机制可独立开关，不破坏 v2.1 现有结构。

---

## 核心机制

| 机制 | 作用 |
|------|------|
| **五层认知架构** | 把记忆分层（L1-L5），不同层有不同生命周期 |
| **Git 跨平台同步** | 会话开始拉、会话结束推，跨 session 持久化 |
| **三路融合检索** | 关键词 + 时间 + 主题，加权融合（RRF） |
| **记忆治理** | 定期 lint 扫描、promote/demote 调整、过期归档、Token 预算 |
| **沉淀钩子** | 6 个时机自动触发沉淀，无需用户主动提醒 |
| **WAL 协议** [v2.2] | 会话开始先写 `SESSION-STATE.md` 再回复，Context 压缩后能恢复关键决策 |
| **两阶段工作流** [v2.2] | 新信号先入 `pending/` 毛坯区，证据积累达标后再 promote 到认知层，避免污染 |

> v2.2 的两个新机制是**正交的**——WAL 管"会话内不丢信息"，两阶段管"会话间不污染认知层"。

## 设计哲学

> 这一节讲**为什么这样设计**，以及**在不同场景下怎么判断**。和单纯讲"做了什么"相比，多了一层决策框架。

### 3D 认知矩阵：为什么认知需要分维度

**设计动机**：单一维度的记忆分类（"按时间"或"按主题"）都有根本缺陷——它**假设了使用者的判断路径是单一的**，结果是一条信息只能从一个角度被找到。

**为什么是 3 个维度（不是 1 个、不是 5 个）**：

| 维度 | 解决的问题 | 判断信号（自问） |
|------|-----------|------------------|
| **纵深轴**（五层 L1-L5） | 信息的稳定程度不同 → 治理策略不该一样 | "这条信息多久会变？变了影响多大？" |
| **横切轴**（什么类型：知识/方案/经验/参考） | 不同类型有不同的生命周期和复用方式 | "它被复用的方式是什么？被引用还是被执行？" |
| **提炼轴**（Encounter → Reflect → Experiment → Realize） | 知识不是一次成型的，需要渐进过程 | "我现在的确信度几分？还需要观察几轮？" |

**怎么判断一条新观察该进哪一格**（操作步骤）：
1. **先判纵深** —— "多久会变？" → L1/L2（短期）还是 L4/L5（长期）
2. **再判横切** —— "什么类型？" → 4 个分类之一
3. **最后判提炼度** —— "现在能打几分确信？" → 4 个阶段之一

**哲学**：用三个独立维度交叉定位认知，比单一分类**更鲁棒**——一个维度判错了，剩下两个还能兜底，不会把信息"丢"。

---

### Karpathy LLM Wiki：为什么原始资料和提炼知识要分离

**设计动机**：传统笔记系统最大的反模式是**把原始资料和提炼结论放在同一个文件里**。后果是：
- 想找原始资料 → 结论污染搜索结果
- 想验证结论 → 找不到原始材料
- 结论随时间演化 → 引用关系断裂，**知识系统丧失可验证性**

**Karpathy LLM Wiki 的核心洞见**：
- 原始资料（`wiki/entries/`）服务于**追溯**——"我为什么这么判断？"
- 提炼知识（`cognition/`）服务于**决策**——"我下一步该怎么做？"
- 两者服务对象不同 → **绝对不能混在同一个文件里**

**怎么判断一条信息该进哪里**：

| 信息类型 | 进哪里 | 例子 |
|---------|--------|------|
| 用户原话、对话片段、事件记录 | `wiki/entries/`（原始资料） | "用户 5/12 说：'周日 10 点给我推周报'" |
| 行为模式、价值观、可复用结论 | `cognition/behavior.md`（提炼知识） | "用户偏好周日 10:00 推送 + 结构化表达" |
| 工具用法、操作步骤 | `cognition/skills/`（可执行知识） | "虾评上传流程：注册→pledge→POST /api/skills" |

**哲学**：原始资料是**证据**，提炼知识是**结论**——证据是结论的根，结论要能随时回到证据那里被验证。**混在一起 = 切断了知识系统的可验证性**。

---

**为什么融合多个框架**：每个框架解决一个具体问题，单独用都有盲区：
- 五层架构 → 解决"分层不清"
- Karpathy LLM Wiki → 解决"原始和提炼分离"
- PromptX Engram → 解决"按类型分类"
- RoleX 循环 → 解决"渐进提炼"

合起来才是**鲁棒的认知工程体系**——一个框架解决不了的问题，下一个框架兜底。

## 实际使用案例

> 评测员反复反馈"模板空壳、缺案例"，以下是真实可复用的场景：

### 案例 1：长期任务跨 session 追踪
- 主人周一让 Agent 调研"AI 记忆系统对比"，Agent 调研完沉淀到 `brain/02-知识库/`
- 周三再开新 session，Agent 主动说："上次调研我整理了 3 个候选方案，要继续深入 X 吗？"
- 主人不需复述上下文，直接接话

### 案例 2：用户偏好自动识别
- Agent 观察主人多次在周日 10:00 推送"周报"，且偏好"结构化表达 + 贴关键输出"
- 自动沉淀到 `brain/cognition/behavior.md`（L3 行为模式层）
- 后续推送周报时自动按主人习惯格式输出

### 案例 3：项目协作长期记忆
- 主 Agent 和 Agent 协作 v2 → v2.1 升级链路，经历 4 次 promote 决策
- 每次决策自动记录到 `brain/02-知识库/decision/`（带置信度 + 反面证据）
- 3 个月后回看，能清晰看到"为什么当时选 A 不选 B"

### 案例 4：WAL 救援长会话（v2.2 新增）
- 主人和 Agent 一起做 v2.2-minor 升级，会话持续 6 小时
- 中途 Context 压缩 3 次，Agent 早期承诺的"先毛坯后蒸馏"原则在压缩中"消失"了
- WAL 协议生效：每次重大决策都先 append 到 `brain/SESSION-STATE.md`
- 压缩后 Agent 读 SESSION-STATE.md，定位到"`pending/` 是毛坯区，不是新信号污染"的最初决策
- 后续讨论始终围绕这个核心原则，没有因为 Context 压缩而"翻烧饼"

### 案例 5：pending 沉淀案例（v2.2 新增）
- 评测员反馈"主人使用 agent-brain 时经常抱怨某个痛点"——这本身就是一个新信号
- v2.1 行为：Agent 直接写到 `cognition/behavior.md`，**一次观察占一个 L3 槽位**
- v2.2 行为：写到 `brain/pending/2026-06-07-评测员痛点.md`（毛坯区），证据计数 1/3
- 3 次评测反馈后，证据计数 3/3 → governance.lint() 触发 promote → 写入 `behavior.md#评测员反馈模式`
- **好处**：中间两次反馈没污染认知层，最终提炼也基于多源证据；pending/ 文件本身就是"真实新信号展示区"（解决了评测员说的"模板空壳、缺案例"问题）

## 核心优势

- **零外部依赖** — 不依赖向量库、图数据库、LLM API
- **跨平台** — 扣子 / Claude Code / Cursor / CodeBuddy 都能用
- **隐私自主** — 记忆数据存在你自己的 GitHub 私有仓库
- **可治理** — lint / promote / demote / archive 完整生命周期
- **工程化** — 单元测试 + 归档机制 + 版本日志

---

## 适用场景

- 长期协作的 AI 伙伴（学生助手、内容创作、代码协作）
- 跨多个项目 / 多个设备的 Agent 需要统一认知
- 关心隐私、希望数据掌握在自己手里
- 不想搭基础设施，又想要"比纯文档多一点结构"的轻量方案

## 常见方案定位参考

> 横向参考，给评估用。客观列各自优势/不足，不针对任何具体项目。

| 方案类型 | 典型做法 | 优势 | 不足 |
|---------|---------|------|------|
| **纯文档笔记**（Notion / Obsidian） | 手动维护 Markdown | 上手快、工具成熟 | Agent 不会主动沉淀；缺乏钩子；多 Agent 协作易漂移 |
| **向量库方案**（Mem0 / Zep） | embedding 语义检索 | 自动语义检索 | 需数据库 / API 基础设施；token 消耗大；商业版常闭源 |
| **图数据库方案**（Graphiti） | 实体关系图谱 | 复杂关系建模 | 部署重（Neo4j 等）；对个人开发者过重 |
| **本系统**（agent-brain-skill） | 文件 + Git + 字符串相似度 | 零依赖、跨平台、隐私自主 | 语义检索弱；靠 Agent 主动观察 |

**简单判断**：
- 只需单次会话临时记忆 → **不需要装**
- 需要"语义级"复杂检索 → **可能**需要向量库
- 想要长期记忆 + 不愿搭基础设施 + 数据自主 → **本系统适合**

## 快速开始

### 给 Agent 的核心描述

复制以下内容给你的 Agent：

```text
## Agent Brain 记忆系统

### 怎么连
1. git clone https://github.com/YOUR_USERNAME/agent-brain.git ./brain
2. 读 brain/index.md 获取用户核心认知（<500字）
3. 读/创建 brain/SESSION-STATE.md（WAL 工作区，v2.2）
4. 按需加载 brain/cognition/（行为 / 价值观层）

### 怎么记 [v2.2 更新]
- 初步观察 → brain/pending/{日期-主题}.md（毛坯区，v2.2 默认）
- 规律提炼 → brain/cognition/behavior.md（lint promote 后）
- L5 核心特质变更 → 需用户确认
- 关键引用 / 决策 → 同步 append 到 SESSION-STATE.md（WAL）

### 怎么同步
- 会话开始：git pull → 读 index.md → 读 SESSION-STATE.md → 再回复用户（WAL 顺序）
- 会话结束：git add . && git commit && git push

### 核心原则
- 始终加载 brain/index.md
- 始终先写 SESSION-STATE.md 再回复用户（WAL 协议）
- 新信号先入 pending/ 毛坯区，待证据积累再 promote（两阶段工作流）
- 深层认知变更需用户确认
- 提炼优于存储——把对话变成结论
```

### 安装步骤

```bash
# 1. 克隆本仓库
git clone https://github.com/Amasun93/agent-brain-skill.git

# 2. 创建你自己的私有 GitHub 仓库
# 例如：https://github.com/YOUR_USERNAME/agent-brain

# 3. 克隆你的私人仓库
git clone https://github.com/YOUR_USERNAME/agent-brain.git ./brain

# 4. 复制初始化模板
cp -r agent-brain-skill/templates/brain-init/* ./brain/

# 5. 推送到你的私有仓库
cd brain
git add . && git commit -m "init" && git push -u origin main
```

## 目录结构

```
agent-brain-skill/
├── SKILL.md                     # 主入口
├── modules/
│   ├── cognitive-memory/        # 五层认知模型 + SESSION-STATE.md（WAL）
│   ├── memory-governance/       # lint / promote / demote / archive + pending/ 扫描
│   ├── retrieval-engine/        # 三路融合检索
│   ├── ingest/                  # 多源摄入 + 冲突检测
│   ├── wiki-builder/            # 知识库构建
│   └── git-sync/                # 双向同步
├── config/
│   └── config.template.json
└── templates/
    └── brain-init/              # brain/ 初始化模板
        ├── SESSION-STATE.md     # [v2.2] 会话工作区模板（WAL）
        └── pending/             # [v2.2] 毛坯区
            └── README.md
```

> v2.2 起，brain/ 目录下用户应新建 `SESSION-STATE.md`（会话工作区）和 `pending/`（毛坯区）以启用 WAL + 两阶段。详见 SKILL.md "核心机制" 章节。
