# RoleX 认知循环参考

## 核心原则

**提炼轴**：从表层接触到底层领悟，解决"信息怎么从浅到深"

---

## 四阶段定义

### Stage 1: Encounter（接触）
**定义**：初次遭遇新信息/新情境

**特征**：
- 被动接收
- 无预设判断
- 记录原貌

**输出**：
- 原始观察记录
- 情境上下文
- 第一印象（待验证）

**时间跨度**：秒级~小时级

**示例**：
```
## Encounter: 用户首次提到"想转行"
- 情境：2024-01-15 对话中
- 原话："最近工作很没意思，想换个方向"
- 情绪：低落但有一丝期待
- 待验证：是真的想转行还是一时情绪？
```

---

### Stage 2: Reflect（反思）
**定义**：对接触到的信息进行主动思考

**触发条件**（满足任一）：
- 同一情境重复出现
- 与已有认知产生冲突
- 情绪反应异常强烈
- 时间充裕时主动触发

**输出**：
- 初步判断
- 假设/假说
- 关联已有记忆

**时间跨度**：小时级~天级

**示例**：
```
## Reflect: 关于"转行"话题
- 关联：用户1年前也提过类似想法
- 冲突：当时说"只是随便想想"
- 假设：可能只是周期性职业倦怠
- 待验证：这次和之前有什么不同？

## Reflect: 区分情绪性表达 vs 真实意图
- 检查点：
  1. 是否有具体目标？（无→情绪性）
  2. 是否有时间压力？（无→可能是念头）
  3. 是否主动寻求建议？（是→认真）
```

---

### Stage 3: Experience（体验）
**定义**：在实践中验证反思阶段的假设

**特征**：
- 主动创造体验机会
- 收集反馈数据
- 记录成功/失败

**输出**：
- 验证结果
- 情境修正
- 经验提炼

**时间跨度**：天级~周级

**示例**：
```
## Experience: 验证"职业倦怠"假设
- 行动：2周内观察用户是否主动提起职业话题
- 结果：未再主动提起
- 修正假设：当前情绪已平复，暂非优先事项
- 提炼：用户情绪性表达周期约2周后会自然消退

## Experience: 验证"周末适合处理重要事务"
- 证据：
  - 12月第1个周六：顺利完成了年度总结
  - 12月第3个周六：主动预约了牙医
  - 1月第2个周六：高效完成了保险规划
- 结果：假设得到验证
- 提炼：周六适合处理"想起来就不安"的事
```

---

### Stage 4: Realize/Master（领悟/精通）
**定义**：将多次经验提炼为稳定认知

**触发条件**：
- 同一假设被验证 ≥3 次
- 情境高度相似
- 无反例出现

**输出**：
- 稳定认知（写入L3-L5）
- 可迁移的规律
- 行为指导原则

**时间跨度**：周级~月级

**示例**：
```
## Realize: 用户决策模式
- 经验基础：6次观察
- 核心规律：
  1. 不会主动开始，需要外部触发
  2. 一旦开始可以持续
  3. 需要"第一步很简单"的启动点
- 行为指导：提供极简第一步，降低启动门槛
- 状态：已沉淀为 L3 Behavior

## Master: 与用户建立信任
- 经验基础：12个月互动
- 核心规律：
  1. 承诺必须兑现（一次失信影响深远）
  2. 不强迫，尊重自主性
  3. 持续稳定 > 偶尔惊喜
- 行为指导：承诺要保守，执行要超预期
- 状态：已沉淀为 L4 Cognition
```

## 认知循环流程图

```
                    ┌─────────────┐
                    │  Encounter  │
                    │   接触      │
                    │ (新信息)    │
                    └──────┬──────┘
                           │
                           ↓
                    ┌─────────────┐
                    │  Reflect    │◄──────────┐
                    │   反思      │           │
                    │ (思考判断)   │    条件触发│
                    └──────┬──────┘           │
                           │                  │
                           ↓                  │
                    ┌─────────────┐           │
                    │ Experience  │───────────┘
                    │   体验      │    验证反馈
                    │ (实践检验)   │
                    └──────┬──────┘
                           │
                           
            ┌──────────────┴──────────────┐
            │                             │
            ↓                             ↓
    ┌─────────────┐              ┌─────────────┐
    │ Realize     │              │   退回      │
    │ 领悟/精通   │              │  前一阶段   │
    │(稳定认知)   │              │(验证失败)   │
    └─────────────┘              └─────────────┘
```

## 快速循环 vs 深度循环

### 快速循环（对话实时）
```
Encounter → Reflect → [判断：是否需要深入？]
                              │
                    ┌─────────┴─────────┐
                    ↓                   ↓
                  是                   否
                    │                   │
                    ↓                   ↓
              记录结论             标记"待验证"
              存入记忆              存入L2
```

### 深度循环（Heartbeat/Calendar）
```
扫描 L2 待验证条目
        │
        ↓
对满足反射条件的条目执行 Reflect
        │
        ↓
关联 Experience 历史
        │
        ↓
提炼结论或更新假设
        │
        ↓
输出：结论 or 新待验证项
```

## 反幻觉校验规则

### 校验1：小样本检验
```
✗ 错误：用户说了1次"我很喜欢运动"，提炼为"用户喜欢运动"
✓ 正确：标记"需多次验证"，存入L2，待积累≥3次证据

✗ 错误：用户骂了1次领导，提炼为"用户对领导有意见"
✓ 正确：标记"情绪性表达"，观察是否持续
```

### 校验2：情境依赖检验
```
✗ 错误：天冷时说"不想出门"，提炼为"用户不喜欢出门"
✓ 正确：标记"情境性偏好"，提炼为"天冷时倾向室内活动"

✗ 错误：在疲惫时说"不想干了"，提炼为"用户想辞职"
✓ 正确：标记"状态依赖表达"，提炼为"疲惫时容易负面思考"
```

### 校验3：言行一致检验
```
✗ 错误：用户说"想减肥"，提炼为"用户决心减肥"
✓ 正确：检查历史行为——之前说过几次减肥？执行了吗？
       → 如执行率<50%，降级为"有意愿但执行力弱"

✗ 错误：用户说"下次注意"，提炼为"用户会改正"
✓ 正确：检查历史——之前说"下次注意"后有改变吗？
       → 如无改变，降级为"习惯性敷衍"
```

### 校验4：可逆性检验
```
✓ 正确提炼示例：
"用户在X情境下倾向于Y"
"当Z条件满足时，用户会W"

✗ 错误提炼示例（绝对化）：
"用户总是Y" → 应为"在A/B/C情境下，倾向于Y"
"用户从不W" → 应为"在现有观察中，未出现W"
"用户是Y型人格" → 应为"暂未观察到与Y相反的行为"
```

## 循环状态标记

每条待验证信息需附带状态：

```markdown
## [信息内容]
- 来源：Encounter记录时间
- 假设：初判是什么
- 验证进度：0/3 (已验证次数/需要次数)
- 反例：暂无 / [记录反例]
- 状态：待验证 | 部分验证 | 确认 | 证伪
- 下次验证时间：[具体时间或条件]
```

## 效率优化

### 并行处理
多个 Encounter 可并行进入 Reflect 阶段

### 批量验证
Heartbeat 时批量检查待验证条目

### 自动升级
```
验证进度 0/3 → 1/3 → 2/3 → 3/3 → 自动升级为"确认"
状态变化时通知用户（可选）
```
