# Cognitive Memory Skill

**认知记忆系统**：专属理解用户的3D认知架构

---

## 一、架构总览

### 3D认知矩阵

```
                    PromptX (横切轴: 信息是什么)
                          ↓
            X1知识 ─── X2方案 ─── X3经验 ─── X4参考
                         ↑
    ┌────────────────────┼────────────────────┐
    │                    │                    │
    ↓                    ↓                    ↓
  L1 状态            L2 情境              L3 行为
(实时变化)         (事件记录)           (行为模式)
    │                    │                    │
    └────────────────────┼────────────────────┘
                         ↓
              RoleX (提炼轴: 怎么从浅到深)
         encounter → reflect → experience → realize
                         ↓
                       L4 认知
                    (价值观信念)
                         ↓
                       L5 核心
                    (底层驱动力)
```

### 提炼循环：认知层的反思机制

**核心理念**：认知层不仅是"描述性"的——记录你是谁、怎么想、怎么做；它还应该是"反思性"的——主动审视这些认知本身是否正确、是否需要更新。

提炼循环是嵌入认知层的自我反思机制。它不追求"记住更多"，而是追求"理解更准"。

**核心三问**：

```
① 有没有新的认知信号？  →  ② 和现有认知矛盾吗？  →  ③ 值得更新吗？
这次对话中有没有新的       新信号和已有记录         证据够吗？
行为模式、偏好、价值观       有冲突吗？             触发阈值到了吗？
```

### 三轴职责

| 轴 | 解决什么问题 | 操作频率 |
|----|-------------|---------|
| **纵深轴(五层)** | 信息放在哪 | 写入时决定 |
| **横切轴(PromptX)** | 信息是什么 | 分类时决定 |
| **提炼轴(RoleX)** | 信息怎么深化 | 定期触发 |
| **反思轴(提炼循环)** | 认知是否需要进化 | 每次深度对话结束 |

## 二、提炼循环详细规范

### 2.1 触发时机

**触发提炼循环的场景**：

| 触发条件 | 描述 | 优先级 |
|---------|------|--------|
| **深度对话结束** | 一次有意义的对话（非闲聊），产生了新的认知信号 | 高 |
| **用户明确指令** | 用户说"记住"、"记一下"、"更新一下" | 高 |
| **检测到认知矛盾** | 新信号与现有认知存在明显冲突 | 高 |
| **定时触发** | Calendar 周任务时批量扫描待验证队列 | 中 |

**不触发的场景**：

- 单次闲聊（无实质信息）
- 纯查询性对话（用户只是问问题，没有表达自我）
- 情绪性爆发（愤怒、激动时的表达，可能不反映真实偏好）

### 2.2 操作流程

#### 第一步：新信号检测

**检查维度**：

```
┌─────────────────────────────────────────────────────────────┐
│  新信号类型                                                 │
├─────────────────────────────────────────────────────────────┤
│  • 行为模式：遇到X时会做Y（之前未观察到）                   │
│  • 偏好表达：对X的喜好/厌恶（之前未记录）                    │
│  • 价值观流露：提到"我觉得应该X"（与现有价值观一致或矛盾）  │
│  • 决策倾向：选择A而不是B（揭示了优先级）                   │
│  • 自我认知：用户对自己的评价（可能有参考价值）              │
└─────────────────────────────────────────────────────────────┘
```

**信号质量判断**：

```
✗ 一次性情绪 → 不记录为信号
✗ 情境性表达 → 降级记录，标记情境
✓ 跨情境一致 → 可能是真实信号
✓ 多次提及   → 高置信度信号
```

#### 第二步：矛盾检测

**检测范围**：检查新信号是否与 `brain/00-共享认知/` 下的已有记录矛盾：

```
brain/00-共享认知/
├── behavior.md     # L3 行为模式
├── cognition.md   # L4 价值观认知
└── core.md         # L5 核心特质
```

**矛盾类型**：

| 矛盾类型 | 描述 | 处理策略 |
|---------|------|---------|
| **情境性矛盾** | 不同情境下表现不同，不算真正矛盾 | 降级表述，添加情境限定 |
| **观察性矛盾** | 两次观察结果不一致 | 进入待验证队列，分析原因 |
| **实质性矛盾** | 与核心认知直接冲突 | 标记"待验证"，不覆盖旧认知 |

**矛盾处理示例**：

```
旧认知：用户"做决策前需要3天冷静期"
新观察：用户在某次紧急情况下快速决策

判断：情境性矛盾（紧急情境vs普通情境）
处理：更新为"在非紧急情境下需要冷静期，紧急情境可快速决策"
```

#### 第三步：证据积累

**证据阈值**：

| 层级 | 证据要求 | 更新方式 |
|-----|---------|---------|
| L3 行为层 | ≥3 次独立观察 | 自动更新（标记来源） |
| L4 认知层 | ≥3 次独立观察 + 无反例 | 用户确认后写入 |
| L5 核心层 | ≥3 次独立观察 + 无反例 + 跨情境一致 | 明确确认后写入 |

**独立观察标准**：

```
✓ 不同时间点的类似行为
✓ 不同情境下的类似反应
✓ 不同对话轮次中的类似表达

✗ 同一次对话中的多次提及（算1次）
✗ 相关但不完全相同的行为（需要单独验证）
```

#### 第四步：更新决策

**决策树**：

```
新信号检测 ──→ 有矛盾？
                    │
        ┌───────────┴───────────┐
        │                       │
        ▼                       ▼
      是                       否
        │                       │
        ▼                       ▼
  进入待验证队列          证据 ≥ 3？
                               │
                    ┌──────────┴──────────┐
                    │                     │
                    ▼                     ▼
                   是                     否
                    │                     │
           ┌───────┼───────┐             继续积累
           │       │       │
           ▼       ▼       ▼
          L3      L4      L5
           │       │       │
           ▼       ▼       ▼
      自动更新   用户确认  明确确认
```

### 2.3 更新规则

#### L3 行为层更新规则

```
条件：≥3 次独立观察验证
更新方式：自动更新
更新内容：
  • 行为模式描述
  • 证据来源引用
  • 置信度标记
更新后：
  • 更新 behavior.md
  • 更新 index.md 索引
  • 追加操作日志
```

#### L4 认知层更新规则

```
条件：≥3 次独立观察 + 无反例 + 用户确认
更新方式：需要用户确认
确认方式：
  • 简单插入: "我注意到你... 这是准确的吗？"
  • 选项确认: "基于观察，你更倾向于A还是B？"
  • 延迟确认: "关于这个我有些假设，等积累更多证据再和你确认"

确认后：
  • 更新 cognition.md
  • 更新 index.md 索引
  • 追加操作日志
```

#### L5 核心层更新规则

```
条件：≥3 次独立观察 + 无反例 + 跨情境一致 + 明确确认
更新方式：需要明确确认
确认方式：
  • "我想确认一下对你的理解——你是一个X的人，对吗？"
  • 提供具体例子说明观察到的现象

确认后：
  • 更新 core.md
  • 更新 index.md 索引
  • 追加操作日志
  • 标记为"已确认核心认知"
```

### 2.4 矛盾处理策略

**核心原则**：新信号与旧认知矛盾时，**标记为"待验证"而非直接覆盖**。

```
┌─────────────────────────────────────────────────────────────┐
│  矛盾处理三原则                                             │
├─────────────────────────────────────────────────────────────┤
│  ① 不删除旧认知                                           │
│     旧认知是历史验证的积淀，不会因为一次矛盾就消失          │
│                                                              │
│  ② 不强行覆盖                                             │
│     新信号只是"可能"，不是"正确"                           │
│                                                              │
│  ③ 标记待验证                                             │
│     让新信号和旧认知并存，等待更多证据                      │
└─────────────────────────────────────────────────────────────┘
```

**矛盾登记格式**：

```markdown
---
id: PENDING-20240115-001
type: 认知矛盾
created: 2024-01-15
status: 待验证
---

## 矛盾描述

**旧认知**：用户做决策前需要3天冷静期
**新信号**：用户在紧急情况下快速决策

## 矛盾分析

可能原因：
1. 情境依赖（紧急vs非紧急）
2. 决策类型（重大vs轻微）
3. 旧认知不准确

## 待验证问题

- 是否在所有决策类型上都存在冷静期需求？
- 紧急情境是否可以打破冷静期？

## 验证进度

- [ ] 第2次验证：下次非紧急决策是否需要冷静期
- [ ] 第3次验证：下次紧急决策的反应
```

## 四、记忆写入规范

### 标准写入格式

```markdown
---
id: L3-B-20240115-001
layer: L3
engram: X3-经验
keywords: 决策,拖延,冷静期,周末
weight: M
created: 2024-01-15
updated: 2024-01-15
status: 待验证
---

## 决策冷静期需求

### 观察
- 时间: 2024-01-15
- 情境: 讨论保险方案
- 表现: 给3个选项后，用户说"我回去想想"
- 结果: 2天后主动回来选择

### 初步假设
用户在重大决策前需要"冷静期"，不是真的"想想"

### 待验证
- 是否每次重大决策都需要冷静期？
- 冷静期一般是几天？
```

### 写入时机

| 触发来源 | 写入层级 | 操作类型 |
|---------|---------|---------|
| 对话实时 | L1-L2 | 快速记录，标记待验证 |
| Heartbeat | L2-L3 | 批量扫描，提炼验证 |
| Calendar | L3-L5 | 深度分析，认知沉淀 |
| 用户明确 | 任意 | 即时写入 |

### 写入质量检查

```
写入前检查:
□ 是否有情境信息？（时间/地点/人物）
□ 是否区分了事实和推断？
□ 是否标记了"待验证"而不是直接下结论？
□ 是否附带了关键词？
```

## 五、提炼流程规范

### Ingest工作流（融合wiki-builder）

```
1. 读 (Read)
   - 收集 L2 待验证条目
   - 关联已有 L3-L5 认知
   
2. 讨论 (Reflect)
   - 执行反幻觉校验
   - 生成/修正假设
   
3. 写 (Write)
   - 提炼结论或更新待验证
   - 更新条目状态
   
4. 更新索引 (Index)
   - 更新 memory/index.md
   - 更新相关层级索引
   
5. 更新关联 (Link)
   - 建立跨层引用
   - 更新与 wiki-builder 的双向链接
   
6. 追加日志 (Log)
   - 记录操作到 memory/log.md
   - 记录提炼过程和依据
```

### 提炼质量控制（关键挑战2）

#### 反幻觉校验四规则

**规则1: 小样本检验**
```
✗ 禁止: 用户说了1次 → 提炼为"用户喜欢X"
✓ 必须: 标记"需多次验证"，待积累≥3次证据
```

**规则2: 情境依赖检验**
```
✗ 禁止: 天冷时说"不想出门" → "用户不喜欢出门"
✓ 必须: "天冷时倾向室内活动"
```

**规则3: 言行一致检验**
```
✗ 禁止: 用户说"想减肥" → "用户决心减肥"
✓ 必须: 检查历史执行率，降级为"有意愿但执行力待观察"
```

**规则4: 可逆性表述**
```
✗ 禁止: "用户总是..." "用户从不..."
✓ 必须: "在X情境下倾向于..." "现有观察中未出现..."
```

#### 校验执行Prompt

```markdown
## 反幻觉校验

### 待校验提炼
"[原始提炼结论]"

### 检查项
1. 验证次数 ≥ 3？
   - 当前: X次
   - [通过/不通过]

2. 有情境限定？
   - [有/无]
   - 如无，添加限定

3. 历史行为一致？
   - [一致/矛盾/待查]

4. 使用绝对化词汇？
   - [是/否]
   - 如是，改为可逆表述

### 结论
[安全提炼/需要修正/不能提炼]
```

### 用户确认机制

**需要确认的场景**:
- 提炼触及 L4-L5（深层认知）
- 结论可能让用户感到被"评判"
- 涉及敏感话题（金钱、健康、人际关系）

**不需要确认的场景**:
- L3 行为观察
- 情境事件记录
- 日常偏好记录

**确认方式**:
- 简单插入: "我注意到你... 这是准确的吗？"
- 选项确认: "基于观察，你更倾向于A还是B？"
- 延迟确认: "关于这个我有些假设，等积累更多证据再和你确认"

## 七、提炼循环触发机制

> 本章节说明提炼循环在什么时机触发，以及与现有触发机制的协同关系。

### 对话结束时的提炼循环触发

**约束**: 深度对话结束才触发，不是每条消息都触发

**操作清单**:
```markdown
### 深度对话结束
□ 执行提炼循环自检（见2.5节）
□ 检测新信号
□ 检查矛盾
□ 评估证据积累
□ 决定是否需要更新
□ 决定更新层级（L3/L4/L5）
□ 需要用户确认时，在下次对话开始时轻提示
```

**触发判断标准**：
- 用户表达了新的行为模式、偏好或价值观
- 用户对某事做出了评价或选择
- 用户分享了新的经历或想法
- 用户纠正了之前的理解

**不触发的情况**：
- 纯查询性问题（用户只是问问题，没有表达自我）
- 确认性对话（用户确认之前的信息）
- 情绪性爆发（需要冷静后再评估）

### Heartbeat 触发

**约束**: 30分钟一次，要快，不能跑重任务

**操作清单**:
```markdown
### 快速扫描 (<5分钟)
□ 扫描 pending.md 中的待验证条目
□ 处理验证进度 ≥2/3 的条目
□ 检查新信号是否积累到阈值
□ 更新索引（只改变化部分）
□ 记录日志（批量）
```

### Calendar 触发

**约束**: 可以跑重任务，产出要存文件

**操作清单**:
```markdown
### 定期任务
□ 周报: 扫描本周新条目，更新索引
□ 月报: 深度提炼，认知更新
□ 季度: 滚动窗口检查，归档

### Lint 健康检查
□ 矛盾检测: 检测认知矛盾，登记到 pending.md
□ 孤儿记忆: 找出无关联条目
□ 缺失关联: 识别应该关联但未关联的条目
□ 提炼循环审计: 检查待验证队列的进展
```

## 八、检索与召回规范

### memory_search 最佳实践

```markdown
## 检索策略

### 基础检索
用户查询 → 直接用 memory_search
- 示例: "用户的决策风格"
- 结果: 关联到 behavior.md 相关条目

### 扩展检索
memory_search 配合层位限定
- 示例: "用户怎么看待工作"
- 限定: layer:L4 OR layer:L5
- 结果: 聚焦价值观和核心驱动

### 关联检索
memory_search 配合关系查询
- 示例: "和David老师的互动"
- 步骤:
  1. memory_search("David老师")
  2. 找到 L3-B001
  3. 读取关联的 L2 wiki条目
```

### 线索词的作用

**实际价值**:
1. **快速定位**: 语义搜索+关键词双重匹配
2. **同义词扩展**: "决策"可匹配"选择""决定""拍板"
3. **跨语言**: 中文语义+英文关键词

**设计原则**:
```markdown
keywords: 决策,选择,决定,拍板,拖延,冷静期
         ↑核心词   ↑同义词   ↑相关词   ↑限定词
```

**注意**: 线索词是辅助，不是主力。真正的检索依赖语义搜索。

### 二级检索流程

```
1. 加载 memory/index.md (<500字)
   → 快速了解用户全貌

2. memory_search 定位条目
   → 找到相关 L2-L5 条目

3. 读取详情（如需要）
   → 按需加载，不撑爆上下文

4. 关联 wiki-builder（如需要）
   → L2 情境详情在 memory/wiki/
```

## 九、淘汰与归档规范

### 权重管理（关键挑战3）

**定性权重替代数值权重**:
```
H (高权重):
- 3次以上验证确认
- 用户主动确认
- 涉及L4-L5

M (中权重):
- 2-3次验证
- 无反例
- L3行为

L (低权重):
- 1次观察
- 待验证
- 可能被覆盖
```

**时间衰减规则**:
```
活跃条目:
- 持续使用，持续验证
- 6个月无更新 → 检查是否归档

待验证条目:
- 3个月无进展 → 降级或归档
- 出现反例 → 立即降级

已归档条目:
- 保留原因记录
- 可恢复，不删除
```

### L2情境层滚动窗口（关键挑战4）

**实现方式**:

```markdown
## 滚动窗口规则

### 保留策略
- 活跃: 最近6个月
- 过渡: 6-12个月，降为低优先级
- 归档: 超过12个月，移入archive/

### 触发时机
- 每月1日检查
- 或条目总数超过阈值时触发

### 操作流程
1. 扫描 memory/wiki/index.md
2. 识别超过6个月的条目
3. 更新状态为"过渡"
4. 超过12个月，移动至archive/
5. 更新索引
6. 记录日志
```

**实际效果**:
- 旧事件不丢失，只是降低检索优先级
- 保持索引精简
- 可恢复，必要时可回溯

### 归档操作

```markdown
---
归档时间: 2024-01-15
归档原因: 超过12个月
合并至: L3-B-202401-002
原始ID: L2-2023-001
---

归档时保留:
- 原始内容
- 归档原因
- 合并目标（如有）
- 操作日志链接
```

## 八、触发机制规范

### 对话实时触发

**约束**: 不能打断对话节奏，要无感

**操作清单**:
```markdown
### 对话开始
□ 检查 memory/index.md（已缓存）
□ 识别用户情绪变化
□ 更新 L1 状态

### 对话中
□ 记录关键陈述（标记待验证）
□ 关联已有认知
□ 必要时轻提示（如"我注意到..."）

### 对话结束
□ 总结新认知（如有）
□ 更新 L2 情境（重要事件）
□ 检查是否需要 Heartbeat 后续处理
```

**时间限制**: 单次操作 <10秒

### Heartbeat 触发

**约束**: 30分钟一次，要快，不能跑重任务

**操作清单**:
```markdown
### 快速扫描 (<5分钟)
□ 扫描 L2 待验证条目（按时间排序）
□ 处理验证进度 ≥2/3 的条目
□ 更新索引（只改变化部分）
□ 记录日志（批量）

### 不做的事
✗ 不做深度提炼
✗ 不更新 L4-L5
✗ 不触发长流程
```

### Calendar 触发

**约束**: 可以跑重任务，产出要存文件

**操作清单**:
```markdown
### 定期任务
□ 周报: 扫描本周新条目，更新索引
□ 月报: 深度提炼，认知更新
□ 季度: 滚动窗口检查，归档

### Lint 健康检查
□ 矛盾标注: 检测冲突认知
□ 孤儿记忆: 找出无关联条目
□ 缺失关联: 识别应该关联但未关联的条目

### 执行流程
1. 读取 memory/log.md（了解上次状态）
2. 执行指定任务
3. 更新相关文件
4. 记录操作日志
```

### 子Agent 触发

**约束**: 需要完整上下文

**操作清单**:
```markdown
### 子Agent 初始化
□ 读取 memory/index.md
□ 读取相关 L3-L5 条目
□ 读取关联 L2 wiki 详情
□ 构建用户画像上下文

### 子Agent 任务中
□ 遵循提炼规范
□ 使用反幻觉校验
□ 记录提炼过程

### 子Agent 结束
□ 汇报提炼结论
□ 主Agent 执行写入
□ 更新索引和日志
```

## 十一、待验证队列规范

### pending.md 的作用

`pending.md` 是提炼循环的"工作台"——存放那些还没完全确认、但值得追踪的认知线索。

**什么时候写入 pending.md**：

| 情况 | 处理 |
|-----|------|
| 新信号被检测到，但证据不足 | 写入 pending.md，标记 1/3 |
| 新信号与旧认知矛盾 | 写入 pending.md，标记"矛盾" |
| 旧认知出现反例 | 写入 pending.md，标记"存疑" |

### pending.md 格式

```markdown
# 待验证队列

## 活跃待验证

### P-001 | 决策冷静期需求 | 1/3
- **类型**: 新信号验证
- **假设**: 用户在重大决策前需要冷静期
- **证据**:
  - [x] 2024-01-15: 讨论保险方案，说"我回去想想"
  - [ ] 还需要2次独立观察
- **下次验证**: 下次遇到决策场景时观察

### P-002 | 沟通风格矛盾 | 待验证
- **类型**: 认知矛盾
- **旧认知**: 用户喜欢直接反馈
- **新信号**: 用户在某些情境下回避冲突
- **可能解释**: 
  1. 情境依赖（公开vs私下场合）
  2. 涉及话题的敏感性不同
  3. 旧认知不准确
- **验证方向**: 区分场合观察

---

## 已完成（可归档）

### P-003 | 拖延但靠谱 | 已确认 → L3-B-005
- **最终结论**: 用户会拖延但最终会交付，属于"慢性子但靠谱"型
- **确认时间**: 2024-02-01
- **合并至**: behavior.md
```

### 验证进展管理

```
验证进度计算：
- 每获得1次独立观察 → 更新 pending.md 进度
- 进度达到 3/3 → 触发更新决策
- 超过3个月无进展 → 降级或归档
- 出现反例 → 立即标记，暂停验证
```

### 与 Lint 健康检查的协同

```
每月 Lint 检查时：
□ 扫描 pending.md
□ 识别超过3个月无进展的条目
□ 识别出现反例的条目
□ 更新条目状态（降级/归档/激活）
□ 记录检查日志
```

## 十二、线索词机制详解

### 线索词的真正价值

**不是冗余的**:
1. **语义增强**: 补充语义搜索可能遗漏的同义词
2. **上下文提示**: 帮助快速理解条目含义
3. **跨语言桥接**: 中文语义+英文标签
4. **精确匹配**: 当需要精确查找时

**设计示例**:
```markdown
## 决策冷静期
keywords: 决策,选择,决定,拍板,拖延,冷静期,周末,重大决定
         ↑核心   ↑同义  ↑近义  ↑反义  ↑情境  ↑时间限定
```

### 线索词生成规则

```markdown
## 线索词生成
每个条目至少包含:
1. 核心词 (1-2个): 最本质的描述
2. 同义词 (1-3个): 语义相近的词
3. 相关词 (1-3个): 情境相关的词
4. 限定词 (0-2个): 时间/条件限定

禁止:
✗ 过长 (超过10个)
✗ 无关词 (强行关联)
✗ 模糊词 (可能,大概)
```

---

## 十一、Lint 健康检查

### 检查项目

```markdown
## Lint 检查清单

### 1. 矛盾标注
- 检测同层冲突认知
- 例: "用户喜欢主动" vs "用户习惯被动"
- 处理: 标记冲突，待验证

### 2. 孤儿记忆
- 检测无关联的条目
- 例: 某行为模式无任何关联事件
- 处理: 建立关联或归档

### 3. 缺失关联
- 检测应该关联但未关联
- 例: L4价值观未关联任何L3行为
- 处理: 补充关联

### 4. 悬空引用
- 检测引用了不存在的条目
- 处理: 清理或修复引用

### 5. 索引一致性
- 检测索引与实际内容不一致
- 处理: 重建索引
```

### 检查频率

| 检查类型 | 频率 | 执行者 |
|---------|------|-------|
| 悬空引用 | 每次写入时 | 自动 |
| 索引一致性 | 每次写入后 | 自动 |
| 矛盾标注 | Calendar周任务 | 自动 |
| 孤儿记忆 | Calendar月任务 | 自动 |
| 缺失关联 | Calendar季度任务 | 需确认 |

## 十二、操作日志规范

### log.md 格式

```markdown
# 认知记忆操作日志

## 2024-01

### 2024-01-15 14:30
- **操作**: 写入新条目
- **条目**: L2-2024-001
- **类型**: 情境事件
- **内容**: 用户讨论保险方案
- **触发**: 对话实时

### 2024-01-15 14:35
- **操作**: 提炼更新
- **条目**: L3-B-001
- **类型**: 行为模式
- **提炼**: 决策冷静期需求
- **验证进度**: 1/3
- **触发**: 对话实时

### 2024-01-15 15:00
- **操作**: Heartbeat扫描
- **扫描**: 12条待验证
- **处理**: 3条
- **触发**: Heartbeat

### 2024-01-15 20:00
- **操作**: Calendar深度任务
- **任务**: 周报生成
- **产出**: 更新索引
- **触发**: Calendar
```

### 日志原则

1. **操作必记**: 每次写入/更新/归档都要记录
2. **记录原因**: 不仅记做了什么，记为什么做
3. **可追溯**: 能从日志重建认知变化过程
4. **不记详情**: 详情在原条目，日志只是索引

## 十三、关键设计决策汇总

### 挑战1: 索引vs详情平衡
- **方案**: 主索引 <500字，始终加载
- **机制**: 二级检索，索引定位+详情按需
- **验证**: 每条记忆都有索引定位信息

### 挑战2: 提炼质量控制
- **方案**: 四规则反幻觉校验
- **机制**: 校验Prompt+用户确认机制
- **验证**: 提炼必须通过校验才能写入

### 挑战3: 记忆膨胀控制
- **方案**: 定性权重+时间衰减+滚动窗口
- **机制**: 6个月活跃/12个月归档
- **验证**: L2情境层有滚动窗口实现

### 挑战4: 与现有文件兼容
- **方案**: 分层迁移+独立维护
- **机制**: USER.md→认知层，MEMORY.md→wiki
- **验证**: 保留过渡期，不强制删除

### 挑战5: SOUL.md与L5区分
- **方案**: 职责分离
- **机制**: SOUL.md是Agent，L5是用户
- **验证**: 两者内容不重叠

### 挑战6: 线索词价值
- **方案**: 语义增强+同义词扩展
- **机制**: 每条记忆附带关键词标签
- **验证**: 辅助语义搜索，不是主力
