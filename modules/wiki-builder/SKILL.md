# Wiki 知识库搭建技能

## 概述

基于 Andrej Karpathy 的 LLM Wiki 方法论（2026-04-04 发布，5000+ ⭐）。

**核心理念：** Wiki 是一个**持久化、复利增长的产物**。知识只编译一次，之后持续更新维护，而非每次对话时重新推导。LLM 负责所有记账工作（交叉引用、摘要更新、矛盾标注），人类负责策划方向和提出好问题。

### 与 agent-brain 其他模块的协作 [v2.2更新]

wiki-builder 与 cognitive-memory、memory-governance 形成完整的"摄入 → 沉淀 → 治理"闭环：

- **ingest 新素材** → 写入 `wiki/entries/`（原始资料，保持 v2.1 行为）
- **写入关键引用** → 同步到 `SESSION-STATE.md` [v2.2 WAL]：长会话中后期可能要找回来的文件路径、关键决策点
- **提炼新模式** → 转入 `pending/` 毛坯区 [v2.2 两阶段]，**不**直接写入认知层

> WAL + 两阶段的完整规范见主 SKILL.md "核心机制" 章节。本模块**轻量引用**，不展开——wiki-builder 的核心职责仍是"持久化知识库"，不是会话工作区或信号暂存。

### 与 RAG 的本质区别

| 对比项 | 传统 RAG（如 NotebookLM）| LLM Wiki |
|--------|----------|----------|
| 工作方式 | 每次查询时从原始文档检索片段 | LLM 增量构建并维护持久化 Wiki |
| 知识积累 | 无积累，每次重新发现 | 持续积累，越用越丰富 |
| 交叉引用 | 查询时临时拼凑 | 已预先建立好 |
| 矛盾处理 | 每次查询时才发现 | 已提前标注 |

## 三层架构

```
┌─────────────────────────────────────┐
│         Schema（CLAUDE.md）          │  ← 告诉LLM如何维护Wiki的规则和约定
├─────────────────────────────────────┤
│           Wiki（知识库层）            │  ← LLM 拥有并维护
│   index / log / 实体页 / 概念页       │
├─────────────────────────────────────┤
│         Raw Sources（原始资料）        │  ← 不可变，用户维护
│   文章、逐字稿、PPT、图片、资料         │
└─────────────────────────────────────┘
```

**分工原则：**
- 👤 **人类**：策划资料、指导分析、提出好问题、思考意义
- 🤖 **LLM**：所有其他一切（摘要、交叉引用、归档、记账）

---

## 标准目录结构

```
{项目目录}/
├── CLAUDE.md              ← ⭐ Schema（最关键配置，告诉LLM如何维护）
├── raw/                   ← 原始资料（不可变，只读）
│   ├── articles/
│   ├── papers/
│   └── assets/            ← 图片等附件
└── wiki/                  ← LLM维护的知识库
    ├── index.md           ← 内容索引（按类别组织）
    ├── log.md             ← 操作日志（仅追加写入）
    ├── overview.md        ← 整体综述（可选）
    ├── entities/          ← 实体页（人物、组织、产品等）
    ├── concepts/          ← 概念页（方法论、框架等）
    ├── sources/           ← 原始资料摘要页
    └── analyses/          ← 分析、对比、洞察页
```

> 简化版（个人/小项目）：可以不建子目录，wiki 页面直接平铺在 wiki/ 下，按主题命名即可。

## 技能模式

### 模式 A：新建 Wiki 知识库

**触发**：用户说"帮我建一个 wiki 知识库"或"为[角色名]搭建 wiki"

**执行步骤**：

1. **确认基本信息**（若未提供，询问）
   - 角色/知识库名称
   - 保存路径
   - 主要知识领域（用于确定 wiki 主题文件和子目录）
   - 规模预期（简化平铺 vs. 完整子目录结构）

2. **创建目录结构**（根据规模选择简化版或完整版）

3. **生成 CLAUDE.md**（最重要，见下方模板）

4. **生成 wiki/index.md 和 wiki/log.md 模板**

5. **提示用户下一步**：将第一批素材放入 raw/，然后触发 ingest

---

### 模式 B：Ingest 新素材

**触发**：用户说"ingest 这个文件"、"消化这份资料"、"新增了素材"

**执行步骤**：

```
新资料进入 raw/
      ↓
1. LLM 读取原始资料
      ↓
2. 与用户讨论关键要点（建议逐个 ingest，保持人工参与）
      ↓
3. 在 wiki/sources/ 写摘要页（或更新对应主题页）
      ↓
4. 更新 wiki/index.md 索引
      ↓
5. 更新相关实体页、概念页
   注意与现有内容的矛盾/印证
      ↓
6. 在 wiki/log.md 追加记录
```

**关键提示：**
- 一个资料可能触及 **10-15 个 Wiki 页面**
- 建议**逐个摄入**，保持人工参与质量
- 发现矛盾时**直接在 wiki 页面标注**，不要掩盖

---

### 模式 C：Query 查询

**触发**：用户提问，需要 LLM 综合 wiki 内容回答

**执行步骤**：
1. 读取 index.md，定位相关页面
2. 精准读取对应页面内容
3. 综合回答，附引用来源
4. ⭐ 好的回答可以存回 wiki（如分析类内容存入 analyses/）

---

### 模式 D：Lint 健康检查

**触发**：用户说"检查知识库"、"lint"、"看看哪里有问题"

**检查项目：**
- 🔴 页面之间的矛盾内容
- 🟡 被新资料推翻的过时内容
- 🟠 没有入链的孤儿页（没有其他页面引用它）
- 🔵 被提到但没有独立页面的重要概念
- ⚪ 缺失的交叉引用
- 🟢 可以通过补充资料填补的知识空白

## 核心模板

### CLAUDE.md 模板（最关键）

```markdown
# {知识库名称} — Wiki 维护规范

## 知识库结构

- `raw/`：原始资料，**只读不写**
- `wiki/`：LLM 维护的知识库，包含：
  - `index.md`：内容索引
  - `log.md`：操作日志
  - `{主题页}.md`：按主题组织的知识页

## Ingest 工作流

每次摄入新资料时，必须依次完成：
1. 读取 raw/ 中的原始资料
2. 与用户确认关键要点
3. 更新或新建对应主题的 wiki 页
4. 更新 wiki/index.md
5. 在 wiki/log.md 追加记录（格式：`## [日期] ingest | 文件名`）

## 页面规范

- **写入 wiki 的内容**：可直接执行的步骤、判断规则、验证过的规律、框架模型
- **不写入 wiki**：原始逐字稿、单纯描述（未提炼成规律）、来源存疑的内容
- 不同来源的同主题内容**合并在同一页**，有冲突时标注来源

## 每次对话开始

先读取 `wiki/index.md`，根据问题定位相关页面，再精准读取，不全量读取。
```

### wiki/index.md 模板

```markdown
# {知识库名称} — 知识库索引

> AI 每次工作前先读这里，定位需要读哪个文件
> 最后更新：{日期}

---

## 知识库文件一览

| 文件 | 用途 | 适用场景 |
|---|---|---|
| [overview.md](overview.md) | 整体综述 | 快速了解全局 |
| [{主题1}.md]({主题1}.md) | {一句话描述} | {什么时候读} |

---

## 使用场景快速导航

**"{典型问题1}"** → {主题文件}#{章节}

---

## Wiki 构建原则

- 按**主题**维护，不按来源维护
- `raw/` 存原始资料，`wiki/` 只存提炼后可执行内容
- 每次新增资料 → ingest → log.md 追加记录
```

### wiki/log.md 模板

```markdown
# Wiki 摄入日志

> 格式：`## [日期] 操作类型 | 来源文件`
> 操作类型：ingest（新增）/ update（更新）/ lint（健康检查）/ query（查询转沉淀）

---

## 待 ingest

| 文件 | 预计影响页面 | 优先级 |
|---|---|---|
| {文件名} | {主题页} | 高/中/低 |

---

## 操作记录

（首次建库，记录从此开始追加）
```

---

## 与 AI 角色配合使用

在角色的系统提示词中注入：

```
每次对话开始前，先读取 wiki/index.md，根据用户问题定位需要读取的文件，
精准读取对应 wiki 页，不要全量读取所有文件。
遇到 wiki 中没有的问题，标注"wiki 暂无此内容"，等待 ingest 补充。
查询时如果产生了有价值的分析，可以存入 wiki/analyses/ 页面供后续复用。
```

## 使用示例

```
新建：为「产品研究搭子」搭建 wiki 知识库，保存在 projects/research-assistant/

Ingest：ingest 这个文件：用户访谈逐字稿_第01期.md

查询：最近三次访谈中重复出现的核心痛点有哪些？

Lint：检查一下这个 wiki 有没有孤儿页或内容矛盾
```
